# Contributing to master-slide-skill

Welcome! This skill helps AI coding agents create distinctive, accurate,
hackathon-ready presentations and deliver an editable PowerPoint `.pptx`.
Contributions from hackathon teams, solo builders, students, founders, and
AI-agent users are all welcome.

## What we welcome

- Fixes to the skill's guidance, policies, or examples in `SKILL.md`.
- Clarifications, accuracy improvements, and typo fixes in this repository's
  documentation.
- New theme directions, slide layouts, or diagram patterns consistent with the
  skill's design principles.
- Improvements to installation, usage, or troubleshooting instructions.
- Issue reports, reproduction steps, and suggested wording for prompts.

## How to report a bug or propose an improvement

1. Open an issue in this repository.
2. Describe what you expected, what actually happened, and which part of
   `SKILL.md` or `README.md` is involved.
3. If it is an accuracy issue, include the source or evidence that supports the
   correction. Do not submit fabricated metrics, claims, or sources.
4. For proposals, explain the problem it solves and keep the change scoped and
   proportional to a small open-source project.

## How to submit a pull request

1. Fork the repository and create a branch from `main`.
2. Make your change. Keep it focused: one issue or topic per pull request.
3. Check that Markdown renders cleanly and links still work.
4. Open a pull request against `main` with a clear description of the change
   and why it helps.
5. Respond to review comments. Maintainers may ask for revisions before merging.

## Quality expectations

- **Accuracy:** every claim, example, and citation must be traceable and honest.
  Never invent statistics, features, customers, or sources.
- **Accessibility:** prefer readable type sizes, sufficient contrast, and
  meaning that does not rely on color alone.
- **Originality:** do not copy another deck pixel-for-pixel or reuse protected
  branding without permission. Treat reference projects as inspiration only.
- **Reproducibility:** instructions should work for another reader following
  them in a comparable agent environment.
- **Respectful conduct:** be welcoming, constructive, and inclusive. Harassment,
  hate speech, and personal attacks are not tolerated.

## Lightweight validation checklist

Before submitting, confirm:

- [ ] `SKILL.md` YAML frontmatter is intact (if touched).
- [ ] Markdown headings, lists, tables, and links render correctly.
- [ ] No fabricated claims, fake metrics, or invented endorsements.
- [ ] References name only sources actually used and claim no affiliation.
- [ ] The change is scoped, readable, and proportional to this project.
- [ ] You have not added secrets, API keys, or personal data.

## Questions

Open an issue. We try to respond promptly, but this is a small project
maintained alongside other work, so patience is appreciated.
